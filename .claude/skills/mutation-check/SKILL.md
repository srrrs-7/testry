# ミューテーション確認

通るだけのテストを残さないための手順。**壊した実装は必ず元に戻す。**

## 手順

1. **対象を決める。** 守りたい挙動を 1 文で書く（例「所有を証明できないディレクトリは gc で消さない」）。
   その挙動を実装している箇所と、落ちるはずのテスト名を特定する。
2. **事前の状態を確認する。** `git status --short` が空であること（空でなければ、未コミットの差分を把握しておく）。
   対象のテストが今は通ることを確認する。
3. **1 か所だけ壊す。** Edit ツールで、挙動を無効にする最小の変更を入れる。例:
   - 判定を常に許可にする / 検査の呼び出しを消す / 条件を反転する
   - 引数を渡さない（`--forbid-only`、`--project`、選択ファイル）
   - エラーを握りつぶす（cleanup の失敗、レポートの欠落）
   
   コンパイルが通る壊し方にする。複数箇所を同時に壊さない（どれを検出したのか分からなくなる）。
4. **該当テストをコンテナ内で実行する**（skill `quality-gate` の「一部だけ」）。
   - 落ちた → 検出できている。落ちたテスト名を控える。
   - 通った → **テストが不足している。** 壊し方が的外れでないか確認したうえで、検出できるテストを足す。
5. **元に戻す。** Edit ツールで戻し、`git diff --stat` で壊した変更が残っていないことを確認する。
6. **戻したあとでもう一度テストを通す。** 最後に `make ci`。
7. **記録する。** `docs/acceptance.md` の「テストの破壊検出の確認（ミューテーション）」の表に、
   壊し方と落ちたテストを 1 行足す。

## 注意

- 編集は Edit / Write ツールで行う。ホストの `sed` / `python3` / `perl` で書き換えない。
- 壊したままコミットしない、壊したまま別の作業に移らない。途中で中断したら、まず戻す。
- 実プロセスや実ブラウザを使うテストは、ランナー自身が後始末をするために落ちないことがある
  （例: グループ外プロセスの回収を止めても、Playwright の契約テストは落ちない）。
  その場合は、その挙動だけを直接確かめるテスト（`tests/process.rs` など）で検出できることを確認する。
- 壊している最中にコンパイルエラー「couldn't find file」が出たら、ファイルの置き換えと重なっただけのことがある。
  もう一度実行する。
