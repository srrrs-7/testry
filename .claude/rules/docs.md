# ドキュメント

- ドキュメントは日本語。コード・コメント・コード内の文言は英語。
- **実行していない検証を「検証済み」と書かない。** `docs/acceptance.md` は進捗の正で、実行して通ったものだけを
  「検証済み」にする。範囲が限られるものは「検証済み（範囲つき）」「ユースケースのみ検証済み」のように範囲を書く。
  実装しないと決めたものは「対象外」（理由の ADR を添える）。
- 対応表のテスト名は実在するものを書く。テストを改名・削除したら同じ変更で直す（agent `acceptance-auditor` で照合できる）。
- 計測値は実際に測ったものだけを載せ、生データ（`docs/benchmarks/`）を残す。改善倍率を約束しない。
  「実行対象を減らした効果」と「オーケストレーションの負荷」を混ぜて書かない。
- 検証していない環境・版は `docs/compatibility.md` で「未検証」と明記する。
- 設計判断を変えたら ADR を足す（`docs/adr/NNNN-<slug>.md`、連番）。既存の ADR は書き換えず、
  新しい ADR から「置き換える」と参照する。利用者の決定は、日付と発言の趣旨を ADR に残す。
- 仕様の正本は `CLAUDE_HANDOFF.md`。仕様中の `dle` は `testry` と読み替える。仕様そのものは書き換えない。
- README の「現在の状態」「既知の制約」は、挙動を変えたら同じ変更で更新する。
